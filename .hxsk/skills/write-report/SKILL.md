## Quick Reference
- **가이드 로드**: `.hxsk/research/solution_comparison_report_guide.md` 로드 없이 진행 금지
- **역피라미드**: 결론과 추천이 Executive Summary 최상단에 없으면 즉시 재작성
- **후보 스크리닝**: 비교 대상 5 개 초과 시 Pugh 매트릭스로 사전 필터링 필수
- **현상 유지 리스크**: "무행동 비용"이 명시되지 않으면 보고서 무효 처리
- **TCO 분석**: 단순 가격 비교 금지, 3-5 년 총소유비용 (9 카테고리) 기반 평가

## Iron Laws
NO EXECUTIVE SUMMARY WITHOUT CONCLUSION AND RECOMMENDATION FIRST
NO RISK ASSESSMENT WITHOUT STATUS QUO OPTION FIRST
NO VISUALIZATION WITHOUT SYMBOLS OR PATTERNS FIRST
NO COST ANALYSIS WITHOUT 3-5 YEAR TCO CALCULATION FIRST
NO EVALUATION CRITERIA WITHOUT MUST-HAVE VS NICE-TO-HAVE DISTINCTION FIRST
NO TECHNICAL TERM USAGE WITHOUT PLAIN LANGUAGE TRANSLATION FIRST
NO NEW REPORT WITHOUT MEMORY PATTERN RECALL FIRST
NO REPORT GENERATION WITHOUT GUIDE LOADING FIRST
NO SOLUTION COMPARISON WITHOUT PUGH MATRIX SCREENING IF MORE THAN 5 CANDIDATES FIRST
NO WEBFETCH EXECUTION WITHOUT SEQUENTIAL PROCESSING FIRST
NO RECOMMENDATION STATEMENT WITHOUT ACTIVE VOICE FIRST
NO SCORE PRESENTATION WITHOUT BUSINESS INTERPRETATION FIRST
NO RECOMMENDATION WITHOUT PREREQUISITES AND RUNNER-UP ANALYSIS FIRST
NO REPORT FINALIZATION WITHOUT MULTI-DEPARTMENT PERSPECTIVE FIRST
NO REPORT SAVE WITHOUT STANDARD FILE PATH STRUCTURE FIRST

## Procedure

### Step 1: 가이드 로드

보고서 작성 요청을 받으면:
1. `.hxsk/research/solution_comparison_report_guide.md` 전체를 Read로 로드
2. 보고서 주제에 맞는 평가 프레임워크 선택 (기본: 가중 평점 매트릭스)
3. 대상 독자 계층 확인 (CEO 1쪽 / C-Suite 3쪽 / 전체 10-20쪽)

### Step 2: 리서치

비교 대상 솔루션별 정보를 수집한다:
- WebSearch로 공식 문서, 가격, 벤더 재무 정보 조사
- **WebFetch는 반드시 순차 실행** (병렬 fetch 금지)
- 비교 대상 3-5개로 제한. 초과 시 Pugh 매트릭스로 사전 스크리닝

### Step 3: 구조 설계

**역피라미드 원칙** — 결론·추천을 최상단에 배치. 아래 섹션 순서를 따를 것:

1. **Executive Summary** (1-2쪽) — 문제 진술, 평가 요약, 핵심 발견, 추천안, 다음 단계
2. **배경 및 범위**
3. **평가 방법론**
4. **기준 및 가중치** (가중치 확정 근거를 비즈니스 용어로)
5. **후보 개요**
6. **평가 결과** (비교 매트릭스 + 시각화)
7. **TCO / 비용 분석** (3-5년)
8. **리스크 평가** ("현상 유지" 옵션 반드시 포함)
9. **추천** (첫 문단에서 제시)
10. **다음 단계**
11. **부록**

### Step 4: 평가 기준 및 가중치

기준 카테고리 표준 (프로젝트에 맞게 조정):

| 기준 | 가중치 범위 |
|---|---|
| 기능 적합성 | 20-30% |
| 보안 및 컴플라이언스 | 15-25% |
| TCO (총소유비용) | 15-25% |
| 통합 역량 | 10-20% |
| 벤더 지속성 | 10-15% |
| 확장성 | 5-15% |
| 지원 및 SLA | 5-10% |
| 도입 용이성 | 5-10% |

**필수**: Must-have(Pass/Fail) vs Nice-to-have(가중 점수) 구분 명시

### Step 5: 시각화 적용

| 유형 | 용도 |
|---|---|
| 막대 차트 | 최종 점수 비교 (기본 필수) |
| 비교 매트릭스 표 | 기준별 상세 (원점수/가중점수, 행별 최고점 볼드) |
| 신호등(RAG) | Pass/Fail 스캔 (색상+기호 병행 필수, 색맹 접근성) |
| 레이더 차트 | 보조 다차원 비교 (선택) |

## 품질 체크리스트

보고서 완성 후 반드시 검증:

- [ ] **역피라미드**: 추천이 Executive Summary에 있는가?
- [ ] **능동태**: "X를 추천합니다" (← "X가 추천됩니다" 금지)
- [ ] **전문 용어**: 첫 등장 시 일반어로 번역했는가?
- [ ] **수치화**: 영향을 정량적으로 표현했는가?
- [ ] **"현상 유지" 리스크**: 무행동 비용이 명시되어 있는가?
- [ ] **차순위 후보**: 미선정 사유가 설명되어 있는가?
- [ ] **추천 전제 조건**: 유효 가정이 명시되어 있는가?
- [ ] **TCO 구분**: 취득/구현/인프라/교육/인력/유지보수/연동/기회비용/전환비용
- [ ] **시각화 접근성**: 색상만 의존하지 않는가? (기호/패턴 병행)
- [ ] **다부서 관점**: IT뿐 아니라 재무/법무/현업 관점이 반영되었는가?

## 안티패턴 경고

보고서 작성 중 아래 실수를 감지하면 즉시 수정:

| 안티패턴 | 수정 방향 |
|---|---|
| 결론이 마지막에 위치 | Executive Summary로 이동 |
| 점수표만 있고 해석 없음 | 각 점수의 비즈니스 의미 추가 |
| 가격만으로 비교 | TCO 3-5년 전체 비교로 전환 |
| 전문 용어 미번역 | 괄호 내 일반어 설명 추가 |
| "현상 유지" 옵션 누락 | 무행동 비용·리스크 섹션 추가 |
| 벤더 마케팅 기반 기준 | 비즈니스 문제 기반으로 재구성 |
