## Design Notes

- The core stack is Bash + Markdown; Python is a system-helper layer, not a package-managed runtime dependency for normal HXSK operation.
- The public taxonomy is best described as POSIX-ish shell CLI conventions + Git hook automation + Markdown-first workflow docs + plain-text file-backed memory.
- The repo is docs-as-code: architecture, decisions, workflow gates, memory, and operational instructions are committed Markdown.
- Optional external CLIs improve validation and forge automation, but core onboarding and workflow remain file-system based.
- Non-core experiments and archives should be documented as evidence/tooling islands so they are not mistaken for runtime requirements.
