# Architecture

> Generated by /codebase-mapper on 2026-04-30

## Overview

HExoskeleton(HXSK)은 AI 에이전트 기반 개발을 위한 경량 워크플로우 보일러플레이트다. 문서화된 코어 런타임은 순수 Bash 스크립트와 Markdown 문서이며, 레포지토리 자체가 배포 단위인 **Self-Configure** 모델을 따른다. 에이전트는 `llms.txt`, `README.md`, `AGENTS.md`, 하네스별 진입 파일, `.hxsk/prompts/setup.md`를 시작점으로 읽고, `.hxsk/`를 단일 진실 원천으로 사용해 스킬·에이전트·훅·메모리·워크플로우를 구성한다. Python/TypeScript 파일은 훅 헬퍼와 비코어 어댑터/실험 도구에 국한된다.

## Components

### Self-Configure Entry Layer
- **Purpose:** Make the repository installable by reading/copying/linking files instead of building artifacts.
- **Locations:** `llms.txt`, `README.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.cursorrules`, `.windsurfrules`, `.github/copilot-instructions.md`, `.hxsk/prompts/setup.md`, `Makefile`, `.hxsk/scripts/bootstrap.sh`, `.hxsk/scripts/install.sh`.
- **Data flow:** Entry docs → setup prompt or `install.sh --harness <name>` → bootstrap/verify → harness-specific settings, links, and optional git-hook fallback.

### Agent-Skill Layer
- **Purpose:** Separate reusable procedure from orchestration: **Skill = How**, **Agent = When/With What**.
- **Locations:** `.hxsk/skills/` and `.hxsk/agents/`.
- **Current index counts:** `.hxsk/skills/INDEX.md` lists 24 skills; `.hxsk/agents/INDEX.md` lists 18 agents; `.hxsk/.bootstrap-version` records version `5.6.1` with 24 skills, 18 agents, 27 hooks, and 17 memory types.
- **Pattern:** Index files are the navigation surface; each skill/agent owns a focused Markdown definition and deeper references where needed.

### Hook Automation Layer
- **Purpose:** Enforce safety and preserve context around agent tool use.
- **Locations:** `.hxsk/hooks/`, `.claude/settings.json`.
- **Events:** SessionStart, PreToolUse, PostToolUse, PreCompact, Stop, SubagentStop, SessionEnd.
- **Key hooks:** `file-protect.py`, `read-before-edit.py`, `write-guard.py`, `track-read-history.py`, `bash-guard.py`, `session-start.sh`, `auto-format.sh`, `track-modifications.sh`, `post-turn-verify.sh`, `stop-context-save.sh`, `collect-rationalization.sh`, `pre-compact-save.sh`, `save-transcript.sh`, `save-session-changes.sh`.

### File-Based Memory Layer
- **Purpose:** Persist agent context as Markdown with YAML frontmatter instead of an external database.
- **Location:** `.hxsk/memories/{type}/` plus `.hxsk/memories/_schema/`; `ADR-006/` remains a historical research artifact outside the canonical type count.
- **Tools:** `.hxsk/hooks/md-store-memory.sh`, `.hxsk/hooks/md-recall-memory.sh`, `.hxsk/scripts/prune-memories.sh`, `.hxsk/scripts/prune-tick.sh`.
- **Features:** YAML frontmatter, contextual descriptions, keywords, `related` 2-hop recall, duplicate avoidance, type-directory auto-create, local/shared retention policy, opportunistic prune triggers with cooldown and stale-lock handling.

### Workflow and Issue Layer
- **Purpose:** Convert goals into gated execution with empirical verification.
- **Locations:** `.hxsk/SPEC.md`, runtime `.hxsk/STATE.md`, `.hxsk/workflow/GATES.md`, `.hxsk/issues/`, `.hxsk/phases/`, `.hxsk/reports/`.
- **Flow:** SPEC → PLAN → EXECUTE → VERIFY → DONE.
- **Parallel mode:** Dispatcher splits work into issue waves with file ownership and worktree merge checks.

### Script and Validation Layer
- **Purpose:** Provide portable Bash utilities for setup, consistency, local verification, forge integration, and release checks.
- **Locations:** `.hxsk/scripts/`, `.hxsk/githooks/`, `.github/workflows/`, `Makefile`.
- **Primary verification entry:** `.hxsk/scripts/local-verify.sh` runs `doc-lint.sh`, `check-consistency.sh`, optional skill scenario dry-runs, and `pre-pr-check.sh`; `.github/workflows/pr-check.yml` runs this bundle for pull requests.

### Harness Adapter Layer
- **Purpose:** Keep HXSK usable beyond Claude Code while preserving `.hxsk/` as the canonical source.
- **Locations:** `.hxsk/adapters/`, `.codex/hooks.json`, `.copilot/hooks.json`, `.github/copilot-instructions.md`, `.cursorrules`, `.windsurfrules`, `.hxsk/githooks/`.
- **Strategy:** Native Claude Code hooks where available, explicit adapter files for other harnesses, opportunistic memory prune triggers, and git-hook fallback for tools without lifecycle hooks.

### Non-Core Research and Tooling Layer
- **Purpose:** Preserve experiments, scenario outputs, and optimizer work without making them part of the runtime path.
- **Locations:** `scenario/`, `predict/`, `reason/`, `learn/`, `security/`, `skill-optimizer/`, `.hxsk/research/`, `.hxsk/tools/skill-doc-optimizer/`.
- **Boundary:** These directories inform roadmap and evidence; they are not required for core install or normal HXSK operation.

## Data Flow

```
1. Onboarding
   llms.txt → AGENTS.md / harness entry doc → .hxsk/prompts/setup.md
   → install/link skills + agents + hook settings → bootstrap verification

2. Normal agent session
   SessionStart → load current context + recall memories
   PreToolUse → protect secrets, enforce read-before-edit/write safety, guard shell commands
   PostToolUse → format and track modifications
   Stop/SessionEnd → verify, save current context, transcript, and memories

3. Planned work
   SPEC.md → PLAN/task decomposition → issue/branch or dispatcher wave
   → executor work → verifier/pre-PR checks → reports and memory updates
```

## Conventions

- **Naming:** Bash and hook scripts use kebab-case; Python hook helpers use kebab-case filenames; core working docs use uppercase names; skill/agent IDs use lowercase kebab-case.
- **Source of truth:** `.hxsk/` owns canonical skills, agents, hooks, scripts, templates, memories, and workflow docs.
- **Documentation style:** Markdown files are versioned source; architecture decisions live in `.hxsk/DECISIONS.md`; indexes should match actual file structure.
- **Shell style:** Bash scripts generally use strict-mode patterns (`set -euo pipefail` or explicit variants), small helper functions, quoted paths, and macOS/Linux portability.
- **Verification:** Completion requires empirical evidence from scripts such as `doc-lint.sh`, `check-consistency.sh`, `local-verify.sh`, and pre-PR checks.
